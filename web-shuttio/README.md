# web-shuttio

The Shuttio web app on **TanStack Start** (Vite, React 19) — the successor of
`../web` (Next.js).

- **Landing page** (`/`) is prerendered to static HTML at build time.
- **Everything else** renders client-side (`defaultSsr: false` in
  `src/start.ts`) and calls the NestJS api directly from the browser with
  TanStack Query, attaching the Clerk session token (`src/lib/api.ts`).
- **Forms** use TanStack Form; **UI** is shadcn/ui on React Aria
  (`aria-luma`); **i18n** is Paraglide (`messages/vi.json`, Vietnamese only
  for now).

## Structure

```
src/
  routes/                    # thin TanStack Router file routes
    __root.tsx
    index.tsx                # -> features/landing (prerendered)
    _auth/                   # pathless auth layout (URLs unchanged)
    _authenticated/          # pathless signed-in layout
      app/                   # player / venue / admin workspaces
  features/                  # one domain module per product area
    admin/ app-review/ assessment/ auth/ booking/ chat/
    dashboard/ landing/ onboarding/ play/ venue/
      api/                   # NestJS calls + React Query factories
      components/            # domain UI
      hooks/                 # domain hooks
      lib/                   # pure helpers / domain logic
      schemas/               # zod form schemas
      types/                 # domain types
  components/
    ui/                      # shadcn primitives
    layouts/                 # app shell, sidebar, topbar, loading/not-found
  lib/                       # cross-cutting infra: api client, env, query
                             # client, shared entities, formatting, tables
  hooks/                     # cross-cutting React hooks
  styles/                    # global Tailwind entry
  router.tsx                 # router + query integration
  start.ts                   # Start config (defaultSsr: false)
  routeTree.gen.ts           # generated by tsr
```

`routes/` only wires URLs to feature components. The `features/*/data.ts`
barrels were removed — import shared entities and helpers from `@/lib/shared`.
`_authenticated` is pathless (renamed from `_signed-in`), so URLs did not change.

There is intentionally no `src/server/` layer: the NestJS app in `../api` is the
backend. Reads and writes go directly from the browser with the Clerk bearer
token (`src/lib/api.ts`); there are no `createServerFn` proxies or BFF routes.

```bash
cp .env.example .env.local   # fill in VITE_CLERK_PUBLISHABLE_KEY
pnpm install
pnpm dev                     # http://localhost:3000
pnpm build                   # .output/ — static index.html + _shell.html SPA fallback
pnpm typecheck && pnpm lint
```

## Docker

From the repo root, with the NestJS api (`dev` stage, Vite dev server):

```bash
docker compose up --build --watch api web-shuttio   # http://localhost:3001
```

The dev image reads `VITE_*` from `.env.local`; the api's comma-separated
`WEB_URL` CORS list allows :3000 and :3001.

The Dockerfile's final stage is production: the Nitro node server on :3000,
pre-compressed assets, non-root, with a `HEALTHCHECK`. `VITE_*` values are
inlined into the bundle at build time, so pass them as build args:

```bash
set -a; . ./.env.local; set +a
docker build -t web-shuttio \
  --build-arg VITE_API_URL="$VITE_API_URL" \
  --build-arg VITE_CLERK_PUBLISHABLE_KEY="$VITE_CLERK_PUBLISHABLE_KEY" \
  --build-arg VITE_MAPBOX_TOKEN="$VITE_MAPBOX_TOKEN" \
  --build-arg VITE_CLOUDINARY_CLOUD_NAME="$VITE_CLOUDINARY_CLOUD_NAME" .
docker run --rm -p 3001:3000 web-shuttio
```

## Deploy (Dokploy)

Create an **Application** with build type **Dockerfile**:

| Setting | Value |
| --- | --- |
| Provider → Build Path | `/web-shuttio` |
| Provider → Watch Paths | `web-shuttio/**` (auto-deploy only on frontend changes) |
| Build Type → Dockerfile Path | `Dockerfile` |
| Build Type → Docker Context Path | `.` |
| Build Type → Docker Build Stage | empty (the final, production stage) |
| Environment → Build Time Arguments | the four `VITE_*` above, production values |
| Domains | your host, container port **3000**, HTTPS (Let's Encrypt) |

`VITE_*` are public values, but they only take effect at build time: change
one and redeploy (a rebuild), not just restart. Also add the frontend domain
to the api's `WEB_URL` and to Clerk's allowed origins.
